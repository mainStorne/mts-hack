    Приемлемое качество за неоправданную цену

Оценка = цена звонка у LLM-провайдера ÷ цена нашего звонка. GLM-5.3: 744 млрд параметров (753 с MTP-слоем), ≈40 млрд активных на токен (карточка модели Amazon Bedrock); наша модель — 1,29 млрд: в 576 раз меньше по всем параметрам, в 31 раз — по активным. Измерено: наш звонок — 2,7 GPU-секунды на V100, около 235 выходных токенов. Диапазон 9–90× — оценка команды по тарифам контакт-центров и прайсам LLM-провайдеров, не измерение.

Обучение

Как обучали

Как обучали

Ансамбль состоит из двух предобученных моделей, реранкера и жадной настройки порогов.

GLiNER

LoRA-адаптер runs/struct-lora-v21

  • Адаптер даёт сырые спаны с уверенностью. Пороги подбираются на dev, не на val.
  • Сначала перебор сетки
  • Затем покоординатный подбор tau по каждому атрибуту (0.3…0.9).
  • Итоговые значения tau_attr:
    service_state0.9tariff0.5ticket_status0.5action0.7agreement0.8
    snap_th 0.5date_tau nulldev F1 0.5602dev_gate_ok false
  • 3 эпохи, около 1 ч 10 мин на V100.

Gemma

LoRA-адаптер gemma-v21-targeted-gen

  • Дообучения этих моделей по фолдам нет. Ансамбль работает с уже готовыми предсказаниями.
  • Данные: train + синтетика + 1 311 звонков, сгенерированных LLM и отфильтрованных (5 402 примера), 3 эпохи, около 2 ч 15 мин на V100.
  • GLiNER обучался только на предоставленном train.jsonl; Gemma — также на сгенерированных данных.

Обучение

Воспроизводимость

Воспроизводимость: сиды, команды, версии

Все входы зафиксированы хешами; цепочка перепроверена на чистой копии репозитория и на другой машине.

# GLiNER: seed 42, 3 эпохи, батч 8×2, LoRA r16 / α32
python cfe/struct_train.py --epochs 3 --batch-size 8 --accum 2 --seed 42 --data struct

# Gemma: seed 42, 3 эпохи, lr 2e-4, батч 4×4, LoRA r16 / α32
python train.py --model gemma-3-1b-it --seed 42 \
  --train-file data/targeted_gen_v21_ctx3k/sft_train.jsonl

# реранкер и проверка входов
python cfe/ensemble.py cv
./repro.sh verify        # sha256 всех входов

Версии: torch 2.14.1+cu126 · transformers 5.23.0 · peft 0.21.3 · gliner2 2.1.0 · uv.lock. Базы: gliner2.5-multi-v1 @ 7b00527, gemma-3-1b-it (sha256 3d4ef8d7…).

  • Порядок сборки данных Gemma: filter_gen → prepare_gemma (real_only, real_plus_targeted) → prepare_dataset (+1 311 LLM-звонков) → 5 402 примера; sha256 sft_train 46316203…
  • Данные GLiNER: train.jsonl → 18 714 пар, негативы 1:1 (сиды 0 и 1); набор заморожен.
  • Проверено: пересборка наборов Gemma на другой машине совпала побайтово.
  • Повторяемость (малый пример, V100, seed 42): веса GLiNER идентичны побитово; у Gemma расхождение 1,2·10⁻³ (fp16-ядра GPU). Критерий для полного обучения — метрики val в пределах ±0,01.

Оператор (реплика 19): «Итого договорённость: блокировка списаний до разбора и запрос на перерасчёт… Подтверждаете?» Клиент: «Да, подходит».

Масштабирование

Микробатчинг очередь

Ставим транскрипции в очередь и обрабатываем их пакетами

Измерено на V100: без батча 14,9 с на звонок, батч 16 — 2,9 с (в 5 раз). У vLLM батчинг внутри сервера: 2,66 с на звонок уже при батче 1 (5 звонков).

Сейчас модель не может обрабатывать несколько запросов параллельно. Можно ввести прикладную очередь: /extract не блокирует лок, а кладёт запрос в queue. Отдельный воркер-батчер копит элементы 5–20 мс (или до K звонков / M контекстов), объединяет контексты разных звонков в один batch_extract, затем раздаёт факты по futures'ам. Так получится эффективнее распределять ресурсы.

Масштабирование

Каскадный роутер

По признакам определяем сложность звонка. Более лёгкий случай — отдаём маленькой модели (GLiNER). Потяжелее — большой (Gemma).

Потолок выигрыша на val: в 15% звонков (58 из 383) ансамбль выдаёт ровно факты GLiNER, в 23% (87) — их подмножество. Пропуск Gemma (1,7 из 2,65 GPU-с) сэкономил бы не больше 10–15% времени.

Развитие · измерено

Flywheel

Flywheel: авторазметка без ручного труда

  1. 01

    GLiNER и Gemma извлекают независимо

    Факт, найденный обеими и прошедший проверки (схема, цитата, тип объекта, реплика, полярность, подтверждение оператора), становится silver — отдельный источник, с gold не смешивается.

  2. 02

    Остальное — в очередь проверки

    С причиной (одна модель, нет цитаты, расхождение дат или реплики) и приоритетом — оценкой реранкера.

  3. 03

    Согласие по датам — признак надёжности

    Даты совпали у обеих моделей — valid_from верна в 93%; не совпали — в 20%. В обучение идёт только temporal_agreed.

Многоязычность

Чтобы добавить новый язык не нужно пересобирать пайплайн заново: достаточно собрать новый каталог атрибутов и поставить соответствующий LoRA Adapter на модель, после чего обучить.
