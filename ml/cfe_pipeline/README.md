# CompactFactExtraction — CPU-пайплайн для ансамбля

Компактный экстрактор фактов: правила предлагают кандидатов, логистические регрессии решают
(«jev-like»). Без GPU и без LLM на инференсе: ~0,2 с на звонок на CPU.

## Запуск
```bash
pip install -r requirements.txt          # Python ≥ 3.10; модели сохранены scikit-learn 1.9.1
./predict.sh calls.jsonl pred.jsonl      # вход — сырой jsonl звонков (формат val/test)
python3 case_metrics.py val.jsonl pred.jsonl
```
`case_metrics.py` ищет `catalog.json` рядом с gold-файлом — как в пакете кейса.

## Выход (pred.jsonl)
Формат звонка из schema.md: в `facts` заполнены `object{type,name}`, `attribute`, `value`, `polarity`,
`speaker`, `valid_from`, `valid_to`, `source{turn_idx, span, quote}`.
Для ансамбля добавлено поле **`_p`** — уверенность судьи (0..1): по нему удобно голосовать/взвешивать.
Оценщик лишние поля игнорирует.

Значения — канонические записи каталога (к действию дописывается «— не помогло», если звучала неудача).
Свободных формулировок пайплайн не порождает: он сильнее в точности и датах статусов, слабее в полноте
договорённостей — хорошо дополняет GLiNER/Gemma.

|---|---|---|---|---|---|---|
| baseline (val) | 0.3348 | 0.3805 | 0.356 | 0.4706 | 0.5345 | 0.7835 |
| пайплайн, **val** | 0.6811 | 0.4678 | 0.555 | 0.4894 | 0.5650 | 0.7717 |

Пороги (`thr_holdout.json`) подобраны на train[3000:], не на val. В архиве — готовые предсказания на val:
`pred_val.jsonl`. OOF-предсказаний на train нет (финальная модель обучена на всём train).

## Как устроено
1. `asr_denoise.py` + `data/asr_model_train.pkl` — очистка ASR-шума («сийчас заяфку» → «сейчас заявку»).
2. `candidates.py`, `textnorm.py` — кандидаты: записи каталога в репликах (лемматизация pymorphy3, нечёткое
   совпадение), статусы заявок по шаблонам, номера заявок, услуги/устройства как объекты.
3. `features.py` + LogisticRegression (`model_full.pkl`) — факт или ловушка (предложение без согласия,
   отвергнутая догадка, отрицание).
4. `pipeline.py` — сборка: объект, якорная реплика (обученный выбор: договорённость привязана к
   подтверждению/фиксации), спикер, полярность.
5. `datelogic.py`, `dates.py`, `datesel.py` — даты: относительные выражения от даты звонка; история статусов
   заявки (принята → в работе → выезд → выполнена, «до X» — конец статуса); цепочки состояний и тарифов;
   обученный выбор даты договорённостей.
6. «Работает нормально» перед поломкой не выдаётся: его начало в разговоре не называется (в эталоне —
   произвольная дата), такой факт только портит temporal.

## Переобучение (Modal, CPU, ~1,5 мин)
```bash
python3 asr_denoise.py fix data/asr_model_train.pkl train.jsonl -o data/train_clean.jsonl
modal run modal_train.py --data data/train_clean.jsonl --out model_full.pkl
```
После этого в модель нужно записать пороги: `m["thr"] = json.load(open("thr_holdout.json"))`,
`m["abstain_past_normal"] = True`.
